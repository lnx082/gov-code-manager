## 一、实习工作

在本次实习中，我参与了集体项目"党政软件版本管控平台"的开发工作，主要负责前端开发、页面重构、架构规划和接口划分四个核心模块，同时承担了系统部署方案的设计任务。

### 1.1 前端开发与页面重构

我负责了项目前端的主体开发工作，完成了 24 个页面组件的编码实现。在开发过程中，我对登录页面进行了重构，采用了毛玻璃卡片配合全屏政务背景的设计方案，并将原有的 mock 数据模式改造为真实 API 对接。针对项目早期存在的大量 emoji 图标和英文副标题，我统一替换为 Element Plus 图标组件，重新设计了白底红饰的整体风格方案，使界面契合党政机关的使用场景。在页面细节层面，我在 Dashboard 工作台中引入了农历日期显示功能，增加了"为人民服务"欢迎语，调整了字体风格和功能模块的四字描述规范，全面提升了系统的政务风格一致性。

### 1.2 架构规划与接口划分

在架构层面，我参与设计了系统三层 BFF（Backend For Frontend）架构方案，明确了前端 Vue 3 单页应用通过 Axios 双通道分别对接 BFF 中间层和 Gitea 代码仓库的通信模型。在接口划分方面，我将前端 API 调用组织为 13 个独立模块（认证、仓库、分支、版本、审批、审计等），统一了请求拦截器、错误处理和 Token 管理逻辑。针对 Gitea API 凭据在 JWT 中传输的安全隐患，我参与了从 JWT 携带凭据到服务端 credentialStore 内存管理的架构改进，实现了凭据不落盘、不传入前端的安全设计目标。

### 1.3 部署方案设计

我负责设计了系统的 Docker 容器化部署方案，包括前端 Nginx 静态托管配置、BFF 反向代理规则、docker-compose 服务编排文件的编写。在开发环境层面，我配置了 Vite 开发服务器代理，解决了前后端分离开发中的跨域问题。此外，我还编写了系统一键启动脚本，降低了项目的环境搭建门槛。

### 1.4 集体项目成果

通过团队协作，我们完成了以下核心成果：前端 Vue 代码（48 个源文件）、基于 Element Plus 的定制组件库、多轮前端 Bug 修复与性能优化、《系统设计文档》（涵盖架构设计、数据库设计、接口设计、安全设计、部署设计五个章节）、系统总体架构图与部署架构图。系统最终实现了 24 个页面、27 个后端路由模块、15 张数据库表、25 种细粒度权限的功能规模，覆盖系统管理员、项目管理员、开发人员、审计人员四种角色。

## 二、参观学习活动

在实习期间，我参观了中安网脉公司，深入了解了该公司在信息安全领域的技术积累和产业发展历程。

### 2.1 企业发展与技术积累

通过参观公司展厅，我了解到中安网脉在数字电话密码机、传真加密机等信息安全设备领域的技术领先地位。公司在内网安全、信息源加密、安全审计等方向的长期投入，使其成为国内信息安全产业的重要组成部分。展厅中陈列的多代加密设备直观展示了信息安全技术从硬件加密到软件防护、从单一设备到体系化方案的演进历程，让我对课堂上学到的密码学理论有了具象化的认识。

### 2.2 行业认知的拓展

参观过程中，我注意到公司在办公应用软件、网络安全平台、信息化密码保障服务的设计、开发、实施等方面也取得了一系列成果。这让我认识到信息安全不仅仅是一个技术问题，更是一个涵盖产品设计、工程实施、运维保障的系统工程。公司从单一加密设备供应商发展为综合信息安全服务商的转型路径，对我理解信息技术产业的商业模式演进有很大的启发。同时，我也了解到国产化替代在当前信息安全领域的重要战略地位，这与我们项目中采用 openGauss 国产数据库、适配麒麟鲲鹏操作系统的技术路线形成了呼应。

## 三、实习总结和体会

### 3.1 从理论到实践的跨越

本次实习让我经历了从课堂理论知识到实际项目开发的完整转化过程。在学校学习 Vue、Node.js 等框架时，往往停留在语法和独立功能的层面；而在实际项目中，我需要同时面对前后端协作、接口设计、状态管理、权限控制、错误处理等多维度的复杂问题。例如，仅仅是 Token 的存储位置这一个看似简单的问题——`localStorage` 还是 `sessionStorage`——就牵涉到多标签页登录独立性、浏览器关闭后 Token 残留、XSS 攻击面等多个安全与体验层面的权衡。这种"真实系统的复杂性"是课堂作业无法模拟的。

### 3.2 团队协作与工程规范

在集体项目中，我深刻体会到软件工程规范对团队协作效率的影响。统一的 Git 提交信息格式、清晰的接口文档、规范的代码注释风格、模块化的文件组织结构，这些看似琐碎的规范在实践中直接决定了团队成员之间协作的顺畅程度。特别是在多人并行开发的情况下，良好的接口划分和模块解耦能够有效减少代码冲突，提高集成效率。

### 3.3 安全意识的全面提升

参与"党政软件版本管控平台"这样面向党政机关的系统开发，让我对信息安全有了远超课堂层面的理解。JWT 中是否应该携带 Gitea 凭据、审计中间件是否应该过滤敏感字段、系统配置接口是否需要管理员权限校验——这些在实际开发中暴露的安全问题，让我认识到安全不是一个"事后添加的特性"，而是需要在架构设计阶段就嵌入系统的核心要素。特别是通过代码评审发现的 39 项改进点，从硬编码凭据到操作符优先级 Bug，让我建立了"安全编码是每一行代码的责任"的意识。

### 3.4 不足与反思

回顾整个实习过程，我也发现了自身的不足之处。一是在项目初期对后端 API 设计的理解不够深入，导致部分前端接口调用方式需要后期待调整；二是在页面性能优化方面经验不足，审批列表等大数据量场景下的加载性能问题是在后期才被发现和修复的；三是在时间管理方面，由于对工作量预估不够准确，部分模块的开发时间超出了预期。这些不足为我后续的学习和成长指明了方向。

## 四、自主学习探索

信息技术领域正处于前所未有的快速变革期——容器化技术改变了软件交付方式，大语言模型重塑了人机交互范式，云计算降低了技术准入门槛。在这样的时代背景下，仅凭课堂所学和项目经验远远不够，终身学习意识和自主学习能力成为技术从业者的核心竞争力。本次实习期间，我通过华为云实验平台自主完成了六项技术实验，覆盖了从基础设施到前沿 AI 的多个技术层面。

### 4.1 容器化技术入门：Docker 的安装部署与镜像管理

我自主完成了 Docker 的完整安装部署流程：从下载二进制包、解压安装、编写 systemd 服务文件，到配置华为云镜像源加速、拉取 Apache 和 CentOS 镜像、通过 `docker run` 创建容器并映射端口和挂载卷、查看容器运行状态。整个过程中我遇到了 Docker 服务无法启动的问题，通过查阅日志和调整 daemon.json 配置最终解决。这一实验让我理解了容器与虚拟机的本质区别——容器共享宿主机内核、启动秒级、资源开销极小，这使得"一次构建、到处运行"成为可能。同时，`docker run` 命令中的 `-p` 端口映射、`-v` 卷挂载、`-d` 后台运行等参数组合，让我建立了对容器网络和存储的初步认知。

更为关键的是，这次 Docker 实验直接支撑了我后续的集体项目工作——我为"党政软件版本管控平台"设计的 Docker 容器化部署方案，正是基于此实验积累的知识。docker-compose 服务编排、Nginx 前端托管、BFF 反向代理、健康检查等配置参数的编写，均源自于对 Docker 核心概念的理解。从个人实验到项目实践的知识迁移，让我深刻体会到自主学习对工程能力的放大效应。

### 4.2 大语言模型部署体验：通过 Ollama 运行 DeepSeek-R1

我通过 Ollama 工具在华为云 ECS 上部署了 DeepSeek-R1 1.5B 版本模型。实验涵盖了 ECS 创建与登录、Ollama 安装配置、模型下载与运行、以及实际对话测试四个环节。选择 1.5B 小参数版本的原因是其权重文件仅约 1.1GB，能够在不使用 GPU 的纯 CPU 环境下流畅运行，适合个人体验和低成本的实验场景。在部署完成后，我测试了模型的文本生成能力，例如要求其生成一份 AI 学习的学习计划，验证了本地部署大语言模型的可行性。

这一实验让我对大语言模型的运行机制有了更直观的认识：模型文件类似于一个压缩的知识库，Ollama 充当了推理引擎的角色，将用户输入的 prompt 与模型权重进行计算得到输出。更重要的是，通过这次实践我意识到，随着模型蒸馏和量化技术的进步，"AI 能力民主化"正在快速变为现实——部署一个可用的语言模型不再需要昂贵的 GPU 集群，一台普通的云服务器即可满足个人级使用需求。

### 4.3 云计算基础设施入门：华为云 ECS 的基本操作

我完成了华为云弹性云服务器 ECS 的基本操作实验，包括创建 Windows 和 Linux 两种系统的云服务器实例、调整云服务器规格配置、修改系统管理员密码、以及云服务器的删除操作。实验中我遇到的一个实际问题是：云服务器的名称未按实验手册要求命名，导致自动化进度检测始终返回 0。排查后发现问题根源在于命名规范——这一经历让我建立了"基础设施即代码"思维中对命名约定重要性的认知。

通过创建 Windows 和 Linux 两种不同操作系统的 ECS 实例，我直观地对比了两者在远程连接方式（RDP vs SSH）、文件系统结构、权限管理模型等方面的差异，为后续在不同操作系统环境下开展开发工作奠定了基础。调整云服务器规格的操作则让我理解了云计算的核心商业价值——弹性伸缩、按需付费，资源的获取和释放可以在分钟级完成，彻底改变了传统 IT 基础设施的采购和运维模式。

### 4.4 Linux 基础技能强化：Shell 脚本编程

我通过两个 Shell 脚本实验强化了 Linux 命令行技能。第一个脚本实现了基本的系统命令调用和信息输出；第二个脚本则引入了循环控制结构，从 `url.txt` 文件中逐行读取 URL 和文件名，通过 `wget` 命令批量下载网络资源。虽然这两个脚本的功能相对简单，但它们帮助我建立了 Shell 编程的核心思维模型——将重复性人工操作转化为自动化脚本。在实际项目开发中，这种思维直接体现在了一键启动脚本和数据库初始化脚本的编写上。

### 4.5 版本控制基础设施实践：搭建私有 Git 服务器

我完成了在 Linux 服务器上搭建个人私有 Git 服务器的完整实验，涵盖 Git 软件安装与配置、创建 Git 用户并设置访问密码、初始化裸仓库并配置用户权限、以及从客户端克隆和推送代码的端到端测试。这一实验帮助我理解了 Git 的分布式架构本质——GitHub/Gitea 并非 Git 本身，而只是 Git 协议之上的协作层。在服务器上执行 `git init --bare` 创建的裸仓库，配合 SSH 密钥认证，就能构成一个最小可用的私有代码管理服务。

这一理解直接影响了我在集体项目中对 Gitea 的角色定位——Gitea 提供的 Web 界面、API 接口、权限管理是 Git 裸仓库的增强层，而我们的 BFF 中间层通过 Gitea API 实现了审批→合并→归档的自动化链路，本质上是将"人手动操作 Git"升级为"系统自动操作 Git"，这背后依赖的正是对 Git 底层机制的准确理解。

### 4.6 后端运行时环境实践：Linux 部署 Node.js

我完成了在 Linux 服务器上部署 Node.js 运行时的实验，包括 Node.js 安装包的下载和配置、以及一个简单的 HTTP 服务器程序的部署测试。部署的测试项目监听了 3000 端口，接收到请求后返回 "Hello World" 响应。这一实验帮助我理解了 Node.js 的事件驱动和非阻塞 I/O 模型——为什么 Node.js 能在单线程模型下高效处理大量并发连接。

将这一实验与 Docker 实验串联起来，我形成了"开发 → 容器化 → 部署"的完整认知链条：在本地完成 Vue 前端和 Express 后端的开发，通过 Dockerfile 定义构建规则，使用 docker-compose 编排多服务协同，最终在服务器上实现一键部署。这种从实验到项目、从分散知识点到系统方法的串联，正是自主学习探索的核心价值所在。
