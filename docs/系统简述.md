# 党政软件版本管控平台 — 系统简述

> **版本**: v3.0 | **日期**: 2026年7月14日
> **技术栈**: Vue 3 + Element Plus + Pinia / Express.js + Knex.js + openGauss / Gitea



## 一、系统概述

"党政软件版本管控平台"是为满足党政机关软件版本管控合规需求而设计的一体化管理系统，围绕**代码仓库管理、版本生命周期管控、多级审批流程、防篡改审计溯源**四大核心业务展开。系统符合等保 2.0 三级安全要求，适配国产化环境（openGauss 数据库、麒麟/鲲鹏操作系统），支持 Docker 容器化一键部署。

系统包含 24 个前端页面、27 个后端路由模块、15 张数据库表、25 种细粒度权限，覆盖系统管理员、项目管理员、开发人员、审计人员四种角色。



## 二、系统架构

系统采用 BFF（Backend For Frontend）三层架构，前端与 BFF 部署于本地，openGauss 和 Gitea 部署于云服务器，前后端分离、数据与代码仓库集中管控。

### 2.3 设计原则

前端不直接操作数据库或 Gitea，所有业务逻辑通过 BFF 统一封装。Gitea 凭据存于 BFF 服务端内存（`credentialStore.js`），不传入前端、不落盘，登出自动清除，重启自动失效。



## 三、核心功能

**用户认证与权限管控**：采用 Gitea 主认证 + 本地 bcrypt 兜底的双通道登录机制，签发 7 天有效期 JWT。四层权限控制体系（路由守卫 → 权限中间件 → 部门隔离 → 界面显隐），管理员首次登录自动配置 Gitea 凭据至服务端。

**仓库与版本管理**：仓库创建绑定部门与密级，分支操作通过 Gitea API 代理实现。支持标准化版本编号、基线冻结/变更/锁定、版本归档与恢复。

**多级审批引擎**：内置多步审批流程，支持自定义模板与步骤→角色映射。审批通过后自动触发后置操作——版本发布自动打 Tag/Release、基线创建自动写记录、归档自动锁定仓库，审批完成即操作完成。

**审计与合规**：所有 API 操作自动记录，提供 SHA-256 防篡改哈希链校验和风险预警引擎（登录异常、高频下载、越权操作、数据泄露检测）。

**部门数据隔离**：非管理员用户自动限制为仅查看本部门数据。



## 四、系统亮点

1. **SHA-256 防篡改审计链**：每条日志包含上条哈希值，形成区块链式单向链，任意篡改均导致后续记录不匹配，提供全链完整性校验接口，满足等保审计溯源要求。

2. **Gitea 深度集成**：不是简单的外挂 Git 仓库，实现了认证借用（用 Gitea 验证用户并自动同步密码）、API 全代理（仓库/分支/PR/Tag 全部通过 Gitea API）、审批联动（审批通过自动打 Tag/发布 Release/冻结仓库）三个层面的深度融合。

3. **审批后置操作自动化**：审批引擎在最终通过时自动执行与操作类型匹配的后置动作，版本发布、基线创建、归档锁定一气呵成，消除人工跟进。

4. **双通道 API + 服务端凭据管理**：业务数据走 BFF、Git 操作走 Gitea 两条独立 Axios 通道，Gitea 凭据仅存服务端内存、不传入 JWT，登出自动清除，重启自动失效。

5. **政务风格 UI**：红色主题、国徽图标、四字功能描述、登录页毛玻璃背景、"为人民服务"欢迎语，整体风格契合党政机关使用场景。

6. **农历日期显示**：Dashboard 展示农历日期，贴合政务办公习惯。

7. **标签页独立登录**：Token 存于 sessionStorage，每个标签页独立会话，关闭即退出，避免 Token 残留。

8. **零配置启动**：数据库模块内建自动建表和 Schema 修复能力，首次部署无需手动执行 SQL 脚本。



## 五、下一步工作

1. **审计日志过滤敏感字段**：当前所有 API 请求体原样写入审计库，登录密码可能被持久化记录，需在记录前过滤 password 等字段。
2. **修复操作符优先级 Bug**：文件差异计算中 `&&` 与 `||` 的优先级问题需加括号修正。
3. **数据库初始化路径统一**：建表和种子数据当前分散在 4~5 处，计划统一迁移至 Knex Schema Builder 作为唯一入口。
